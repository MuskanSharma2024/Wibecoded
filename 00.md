# Antigravity Prompt — Feed UI: rejection count + live status

Paste this into Antigravity as the next instruction after the initial feed UI build.

---

Update the homepage feed UI with two additions:

## 1. Rejection count per tick
Each published post's `rejected_topics` row (or however rejections are being
tracked from the tick pipeline) should surface a small line near that post,
or as a running total near the top of the page:

"N topics rejected this cycle — <most common reason category>"

This should be visible without expanding anything (not buried inside the
"Behind the scenes" collapsible) — it's meant to be a quick, skimmable signal
that editorial judgment is real and not just publish-everything.

Data source: query `rejected_topics` table, either:
- grouped by the most recent tick timestamp (if tick runs are distinguishable), or
- as a simple total count + most recent 1-2 reasons, if ticks aren't separately tracked

Style: same terminal aesthetic as the rest of the page, muted/dim text color,
small font size — this is secondary information, shouldn't compete visually
with the posts themselves.

## 2. Live status indicator
Add a small line near the top of the page (near the "Vera_Log" header) showing:
- Status: Active / Autonomous (already exists)
- Last tick timestamp (when the most recent tick ran, published or not)
- Optional: approximate time until next tick, if the cron interval is known
  client-side (e.g. "next check in ~X min" computed from last tick time + 2h)

This should read from the most recent row across `posts` and `rejected_topics`
combined (whichever is newer) so it reflects tick activity even in cycles
where nothing got published.

## Constraints
- Keep it a Server Component fetch, same pattern as the existing page — no
  new client-side polling needed, this can just reflect state as of page load
- Don't break the empty state (no posts yet) — in that case just show
  "Status: Active — first tick pending" or similar, no rejection count needed
- No new dependencies

## Verification
- Run `npm run dev`, confirm the rejection line and live status render
  correctly against real data from at least 2-3 completed ticks
- Confirm empty state (fresh agentId with no posts/rejections) still renders
  without errors
